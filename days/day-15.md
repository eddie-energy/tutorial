**Goal**:

## Step 1 — Persisting near real-time data

At the end of day 14 we used the REST outbound to retrieve near real-time data generated by AIIDA.
Before we implement anything, let's take a look at the received messages.
We will use the CIM format for maximum compatibility with different EDDIE and AIIDA versions.

```shell
curl http://localhost:9090/outbound-connectors/rest/cim_1_12/near-real-time-data-md | jq
```

From the API we receive messages in envelopes of header and document.
The snippet below highlights the fields of such a message that are relevant for our implementation.

```json
{
  "MessageDocumentHeader": {
    "MetaInformation": {
      "connectionId": "1",
      "requestPermissionId": "26bb7819-490d-4992-a5e3-884963b6df8f"
    }
  },
  "MarketDocument": {
    "TimeSeries": [
      {
        "dateAndOrTime.dateTime": "2026-05-19T09:26:11Z",
        "Quantity": [
          {
            "quantity": 68,
            "type": "0",
            "quality": "AS_PROVIDED"
          },
          {
            "quantity": 1538,
            "type": "3",
            "quality": "AS_PROVIDED"
          }
        ]
      }
    ]
  }
}
```

Similar to the validated historical data messages, the header includes the connection and permission IDs.
The document itself holds the readings as `Quantities` of different types and qualities.
You can find a full list of types on the [AIIDA documentation](https://architecture.eddie.energy/aiida/1-running/schemas/cim/real-time-data-market-document.html#type).
For now use the reading with type 0, which is total energy consumed in kWh.

With this in mind, we start by adding another method to our `EddieRestClient`.
Note that we import a specific version of `RTDEnvelope`.

```java [EddieRestClient.java]
import energy.eddie.cim.v1_12.rtd.RTDEnvelope;

public void nearRealTimeData(Consumer<RTDEnvelope> consumer) {
    client.get().uri("/cim_1_12/near-real-time-data-md")
            .accept(MediaType.TEXT_EVENT_STREAM)
            .retrieve()
            .bodyToFlux(RTDEnvelope.class)
            .doOnError(error -> LOGGER.error("Error while retrieving near real-time data", error))
            .retryWhen(Retry.backoff(Long.MAX_VALUE, Duration.ofSeconds(5)))
            .subscribe(consumer);
}
```

In the `MeterReadingService`, we add a new method to handle the incoming near real-time data messages.

```java [MeterReadingService.java]
private void handleNearRealTimeData(RTDEnvelope message) {
    var meta = message.getMessageDocumentHeader().getMetaInformation();
    var connectionId = meta.getConnectionId();
    var permissionId = meta.getRequestPermissionId();

    var meterReadings = new ArrayList<MeterReading>();

    for (var series : message.getMarketDocument().getTimeSeries()) {
        var timestamp = series.getDateAndOrTimeDateTime().toInstant();

        for (var quantity : series.getQuantities()) {
            if (quantity.getType() == QuantityTypeKind.TOTAL_ACTIVE_ENERGY_CONSUMED_KWH) {
                var value = quantity.getQuantity().multiply(BigDecimal.valueOf(1000));
                var reading = new MeterReading(connectionId, permissionId, timestamp, value);
                meterReadings.add(reading);
                break;
            }
        }
    }

    repository.saveAll(meterReadings);
}
```

Then inside the `MeterReadingService` `init` method we subscribe that handler to our message stream.

```java [MeterReadingService.java]
@PostConstruct
void init() {
    eddie.validatedHistoricalData(this::handleValidatedHistoricalData);
    eddie.nearRealTimeData(this::handleNearRealTimeData);
}
```

We still need a way for users to connect their AIIDA data,
so add a new EDDIE button to your `app.html`:

```html [app.html]
<br />
<eddie-connect-button
        [attr.connection-id]="userId()"
        data-need-id="00000000-0000-0000-0000-000000000004"
>
    Near Real-Time Data
</eddie-connect-button>
```

The chart we built on day 12 already queries all stored readings for the authenticated user.
As soon as new AIIDA samples arrive and are stored in the `meter_reading` table,
the existing automatic refresh in the frontend will pick them up and extend the displayed curves.

## Checkpoint

- Your backend subscribes to the near real-time REST stream exposed by EDDIE
- Near real-time AIIDA samples are stored in the same `meter_reading` table as historical data
- Users can create a near real-time permission from the application UI
- The existing chart starts reflecting newly arriving AIIDA readings without additional frontend changes
